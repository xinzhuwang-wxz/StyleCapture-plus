# 用户像素形象透明精灵链路

## 目标

让用户上传全身照后，异步生成像素角色卡，并在同一个 Worker 任务中生成独立的透明 PNG 精灵；进入像素世界时使用透明精灵，保留现有单图程序动画作为四姿态生成上线前的回退。

## 用户可见结果

- 「我的」页面仍展示有背景的像素角色卡。
- 像素世界只绘制透明背景的小人，不再把整张卡片带入场景。
- 卡片与透明精灵属于同一次真实生成任务，均可删除且保持用户隔离。
- 透明精灵尚未准备好时，客户端不会伪装成成功结果。

## 范围

1. 后端从真实像素卡产物生成透明 PNG 衍生图并写入对象存储。
2. PixelTrial 领域、持久化和 API 同时暴露卡片与精灵两个私有结果。
3. H5 在像素世界入口读取当前 PixelTrial 的透明精灵。
4. 保留现有 `idle / walk / cheer / wave` 资源模型；本计划不生成四姿态图片。

## 意外与发现

- 现有像素世界已经能加载透明图片并对单图执行程序化动作，但当前用户来源只有 `assetUrl`，没有接入 Profile PixelTrial。
- PR #49 正在稳定角色卡生成 Prompt，透明衍生步骤应基于该分支，避免并行修改同一个生成入口。
- 两张 PR #49 风格锚点的实图检查均成功移除卡片背景和装饰；首版最大连通域策略可能舍弃与身体完全断开的手持饰品，后续可在真实样本增多后再引入更强的人像分割回退。
- 用户提供的像素卡暴露了“地毯与鞋底相接”的真实边界；实现已改为直接复用离线脚本的背景色板泛洪，并增加仅从画面下方两侧进入的支撑面清理。实图复查保留了人物、手机和背包，同时移除边框、标识、星星与地毯。

## 验证结果

- 后端 PixelTrial：9 个测试通过（含透明 PNG、接触鞋底的地毯、失败诚实性、私有下载与级联删除）。
- 后端静态检查：Ruff 与 mypy 通过。
- H5：30 个测试文件、247 个测试通过，TypeScript 类型检查通过。
- H5 生产构建通过；localhost 已实际进入并退出像素世界，入口和场景加载正常。
- 未使用用户照片触发真实供应商生成：本轮没有一张经用户授权、可发送给供应商的新输入图；生成供应商本身由既有 PixelTrial 合同和处理测试覆盖。
