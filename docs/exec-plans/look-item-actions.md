# 穿搭单品操作与单品详情精简

## 目标

让穿搭详情中的单品点击后直接显示基于后端归属状态的操作面板；精简单品详情，并让归属修改即时保存。相册/拍照默认“已拥有”，Feed 默认“未拥有”。

## 用户可见结果

- 穿搭详情点击已拥有单品：显示“已拥有，去搭配”。
- 穿搭详情点击未拥有单品：显示“未拥有，去购买”和“检测与已有穿搭的适配度”。
- 购买动作打开后端返回的抖音商城搜索链接；搭配和适配度动作进入 AI 推荐页并携带单品。
- 单品详情删除来源/处理标签、展示图说明和单品描述；归属文案改为“已拥有 / 未拥有”，点击即保存；删除保存按钮；“用这件搭一套”右侧增加购物车按钮。

## 实施步骤

1. 扩展单品 API 响应，返回购买搜索词和抖音搜索链接；补来源默认归属策略。
2. 为穿搭详情单品增加操作面板，并接入 App 的 AI/购买导航。
3. 精简单品详情并实现归属、分类即时保存和购物车按钮。
4. 更新生成的 API 合约与前后端测试。
5. 在手机视口完成实际点击、跳转和视觉复核。

## Decision log

- 归属以 `ItemResponse.ownership` 为唯一判断依据，不从卡片文案或来源在前端二次推断。
- 来源只决定首次录入的默认值；用户在单品详情修改后，以持久化值为准。
- “检测适配度”当前复用 AI 推荐锚点入口，后续可在不改弹层契约的前提下增加专用模式。
- 对尚未生成 `item_id`、但后端已有采购需求的穿搭位置，按未拥有显示同一操作面板。

## Surprises & discoveries

- Feed 客户端已经显式传入 `inspiration`，但提交 API 原先要求所有来源都显式传 ownership；相册/拍照没有后端默认策略。
- 已保存穿搭的采购需求可关联 inspiration 单品，并已经携带可用的抖音搜索 URL。
- 本地正在运行的后端尚未重启，旧响应没有购买字段；前端加入兼容回退，滚动发布期间仍能生成有效抖音搜索链接。
